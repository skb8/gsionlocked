# iQOO Neo10 CN / PD2425: диагностический порт

## Результат

Это основа порта для PD2425 / SM8650 / Android 16 / OriginOS 6 с уже
полученным временным root GhostLock + KernelSU LKM. **Запуск GSI на Vivo
не реализован и не проверен.** APK и native preflight не являются установщиком
полного runtime. Совпадение OTA не включает запуск.

В APK добавлены определение PD2425 и диагностика device/model/API/ABI/fingerprint
без root. Start завершается отказом до подготовки launcher и запуска root-сессии.
В Samsung loader/guardian добавлена безусловная ранняя проверка model/device/API/
bootloader, независимо от TEMPGSI_HAL_PROFILE151. Проверка добавлена и в
EvoxWork198 до файловых операций и SELinux lease. Существующие проверки образа,
хешей, prepared profile и изоляции сохранены.

PD2425 loader/guardian сейчас являются **только диагностическими программами**.
Они принимают --check-host, --diagnose, --diagnose-json и отдельный --test-cgroup; остальные операции запрещены.
Профиль содержит launch_enabled=false. Проприетарные файлы Vivo в Git не включены.

## Init, HAL, VINTF и SELinux

| Подсистема | Данные OTA | Препятствие |
| --- | --- | --- |
| Дисплей | vendor.qti.hardware.display.composer; Composer3 AIDL v2 | Нужны ownership, приватный Binder и точное восстановление |
| Аудио | vendor.audio-hal; HIDL audio 7.1/effect 7.0 | Иной бинарник и граф restart; Samsung sec-audio неприменим |
| Power/Lights/Health | vendor.power / vendor.qti.light / vendor.health-default | Иные пути и контракты процессов |
| Камера | vendor.camera-provider, QTI/Vivo интерфейсы | Samsung provider и shims неприменимы |
| Отпечаток | biometrics-fingerprint; IFingerprint AIDL v3 | Домен vivo_hal_fingerprint и иной адаптер |
| Gatekeeper | Объявлены QTI default и SPU варианты | Активный вариант нужно определить на устройстве |
| Температура | thermal-engine и vendor.thermal-hal | OEM thermal mitigation должна работать |

QTI composer имеет onrestart restart surfaceflinger; SurfaceFlinger перезапускает
работающий zygote. Audioserver перезапускает несколько audio HAL, а vendor
HAL перезапускает audioserver. У zygote есть действия рестарта других служб
и vivo.zygote_restart; найден zygote_third. Остановка двух Samsung zygote не
является проверенным протоколом quiesce для OriginOS.

Основной manifest, manifest_pineapple.xml, manifest_cliffs.xml и fragments
не следует механически объединять в активную конфигурацию. Профиль сохраняет
офлайн-декларации, а не инструкции по остановке служб.

Найдены goodix_ts.ko, включая каталог 6.1-gki, и VTS paths /sys/class/vts/vivo_ts
и /sys/touchscreen. Семантика записи для передачи дисплея/ввода не доказана.
Samsung запись `2,1`/`1,0` в /sys/class/sec/tsp/enabled на Vivo не добавлена.

Composer file label — hal_graphics_composer_default_exec; fingerprint —
vivo_hal_fingerprint_exec. File label не доказывает фактические credentials,
transition и effective SELinux allow. Совместная работа system 36 и vendor
policy 34.0 требует проверки полного policy/mapping, а не копирования Samsung
groups/capabilities/identities.

Исходный EvoxWork198 вызывает setenforce 0 и пытается вернуть исходный режим.
Enforcement общий для ядра, mount namespace его не изолирует. Автоматическое
отключение SELinux для PD2425 не включено. Enforcing-совместимость и надёжное
восстановление ещё не реализованы.

Samsung guardian требует watchdog fd у system_server с identity Software Watchdog,
timeout 100, KEEPALIVE и MAGICCLOSE. OTA не устанавливает живого владельца fd,
armed-state или доступность pidfd_getfd. PD2425 preflight не открывает watchdog.

## Установка и диагностика

APK versionCode 202, versionName 0.1.5-pd2425-isolation-probe. Debug APK подписан
тестовым ключом, без опционального встроенного KernelSU APK. Разные CI-сборки
могут иметь разные debug-ключи. Обновление поверх приложения с иной подписью
не сработает; удаление приложения удаляет его импортированные файлы.

```
adb install gsionlocked.apk
```

На PD2425 откройте «Диагностика PD2425». Root для неё не требуется. Check root
использует существующий backend приложения; uid=0 не доказывает версию/тип root
или возможность handoff. Root нужно получить и разрешить отдельно.

Расширенный read-only отчёт:
```
python tools/diagnose_pd2425.py --output pd2425-diagnostics.json
python tools/diagnose_pd2425.py --root --output pd2425-root-diagnostics.json
```

--root использует уже авторизованный su. Скрипт читает ограниченные properties,
состояния служб, имена input, watchdog metadata, cgroup, uname, SELinux; с root —
modules и хеш живой policy. Ошибки чтения сохраняются. Serial из --serial не
записывается. Код 4 означает совпадение OTA при неготовом runtime; 2 — несовпадение.

Native-проверка:
```
adb push guardian-pd2425-preflight /data/local/tmp/
adb shell chmod 755 /data/local/tmp/guardian-pd2425-preflight
adb shell /data/local/tmp/guardian-pd2425-preflight --diagnose
```

Push/chmod создают только диагностический файл на userdata. Программа не меняет
службы, SELinux или mounts. Для --check-host/--diagnose код 0 означает совпадение точного профиля хоста; 31 — mismatch;
78 — запрещённую операцию. Всегда выводится runtime_ready=0. Loader preflight
имеет тот же контракт. Это не штатные loader/guardian запуска GSI.

Не устанавливайте Samsung prepared profile, work198.jar, shims или чужие
calibration/biometric данные на Vivo. Для этой версии не нужны fastboot flash,
запись в block devices, изменение vbmeta/boot/init_boot/vendor_boot/super.

## Сборка и проверки

Linux x86_64, JDK 17, SDK platform 35/build-tools 35.0.0, NDK 25.2.9519653:
```
python tools/audit_public.py
python tools/test.py
python tools/test_pd2425.py
python tools/test_live_probe.py
python tools/test_profile_review.py
python tools/test_cgroup_probe.py
python tools/build_app.py --debug
python tools/build_runtime.py --sdk "$ANDROID_HOME" --java-home "$JAVA_HOME"
```

Задайте ANDROID_HOME, JAVA_HOME, при необходимости ANDROID_NDK_HOME.
Runtime build.json содержит SHA-256 и статус компонентов. Собираются
Samsung loader/guardian и dex jar для ревью, PD2425 preflight,
artd-session.so, private-selinux-mount.so, property seeder, soft-keymint-service
и два Android native test binary. Это не полный установочный комплект.
Soft KeyMint требует внешней реализации и соответствующего ABI.

Локально после восстановления пройдены C identity/CLI/gate tests, проверка
multiline init/VINTF parser, Python syntax и audit_public. Java/APK/native Android
сборку текущего состояния проверяет CI. Native storage/UID тесты лишь собираются;
исполнение требует целевого Android ядра/root и здесь не заявлено.

Для повторного извлечения OTA:
```
payload-dumper-go -p vendor,odm,product,system_ext,vendor_dlkm,vendor_boot,init_boot,system -o images ota.zip
fsck.erofs --extract=fs/vendor --no-preserve images/vendor.img
fsck.erofs --extract=fs/odm --no-preserve images/odm.img
fsck.erofs --extract=fs/product --no-preserve images/product.img
fsck.erofs --extract=fs/system_ext --no-preserve images/system_ext.img
fsck.erofs --extract=fs/vendor_dlkm --no-preserve images/vendor_dlkm.img
fsck.erofs --extract images/system.img
dump.erofs --cat --path=/system/build.prop images/system.img
```

Сохраните выбранные system init/SELinux/VINTF files в system-selected:
```
python tools/analyze_pd2425.py --tree fs --system-selected system-selected --output inventory.json
```

Анализатор не выбирает активные imports/VINTF variants и не вычисляет effective
SELinux policy или ABI-совместимость. Образы/распаковку держите вне репозитория;
для полной распаковки нужно значительно больше диска, чем размер ZIP.

## Следующий этап: live probe (0.1.4)

Предыдущий Actions run для c80bc6d успешно собрал APK, весь публичный runtime
и выполнил тесты. Это доказательство сборки, а не возможности takeover на Vivo.

В 0.1.4 добавлен native JSON probe, включённый в APK как arm64 executable в
nativeLibraryDir. Он запускается через существующий KernelSU/su backend по
кнопке **«Root-отчёт PD2425»**. Root нужно разрешить отдельно. Запуск бинарника
на самом PD2425 ещё требует проверки; отказ SELinux/KernelSU будет показан как
ошибка, без попытки обхода.

Отчёт фиксирует:

- Версию ядра, enforcement, battery temp и cgroup v2 controllers с errno чтения.
- Состояния init-служб и init.svc_debug_pid. Для процесса читаются exe, starttime,
  Uid/Gid/Groups/CapEff и SELinux context. Эти данные повторно сверяются в конце
  чтения: смена PID/starttime, credentials, exe/context или состояния init
  делает snapshot_stable=false. Это ограниченное наблюдение, а не замораживание
  процесса или проверка его доверенности.
- Если init PID property недоступна, уникальный среди видимых процессов match
  executable фиксируется только как pid_source=exe_candidate. Это не доказанный
  владелец init-службы. Несколько совпадений остаются неоднозначными; ошибки и
  ограничения сканирования сохраняются.
- Возможности KEY_VOLUMEUP/KEY_VOLUMEDOWN/BTN_TOUCH через read-only EVIOCG*
  запросы. События клавиш и касаний не читаются, EVIOCGRAB не используется.
- Метаданные watchdog0 и ссылки на watchdog fd в system_server. Устройство
  /dev/watchdog не открывается, fd не дублируется, KEEPALIVE/options не меняются.
  fd_adoption_tested=false остаётся обязательным ограничением.

Список наблюдаемых служб генерируется из профиля при сборке APK/runtime,
включая zygote_third, framework и thermal-службы. Это не список для ctl.stop.
Режим --diagnose-json не содержит service control, mount, setenforce или записи в sysfs. Отдельный --test-cgroup описан ниже и создаёт временную cgroup только для своих процессов.

После успешного сбора нажмите **«Сохранить root-отчёт»** и выберите файл JSON.
Отчёт не отправляется автоматически. Он содержит технические PID/UID/контексты,
а не serial, calibration, биометрию или содержимое пользовательских файлов.
Открытие приложения с root само по себе не включает запуск GSI.

При работе через ADB можно использовать runtime binary:
```
adb shell su -c '/data/local/tmp/guardian-pd2425-preflight --diagnose-json' > pd2425-live-report.json
python tools/review_pd2425.py pd2425-live-report.json --output pd2425-review.json
```

Native mismatch возвращает 31, сохраняя JSON. В APK такой отчёт можно сохранить
для разбора несовпадения; это не отключает launch gate. Native schema-2 JSON и
старый отчёт diagnose_pd2425.py имеют разные схемы: review_pd2425.py принимает
только native schema 2.

Review проверяет исходные поля identity самостоятельно, root UID, enforcing,
температуру, metadata/errors, наблюдения процессов и возвратные key capabilities.
Даже observation_checks_passed=true оставляет runtime_ready=false. Проверка не
генерирует runtime authorization или команды изменения служб. PID-кандидаты
не считаются подтверждённым init PID. Список необходимых физических проверок
остаётся в каждом review.

Тест test_live_probe.py использует вымышленные proc/sys/dev данные. Проверены
PID/state races, статический starttime parser с пробелами/скобками в comm,
недоступные contexts, несколько executable candidates, JSON escaping и ошибки
input ioctl. Тест перехватывает open/ioctl: write opens, открытие watchdog и
setter ioctl приводят к отказу теста. Это проверяет код probe, а не прошивку Vivo.

Для следующего этапа адаптации нужен именно live JSON с реального телефона.
Без него нельзя обоснованно выбрать HAL identities, service ownership,
watchdog recovery и протокол quiesce. После отчёта всё равно потребуются
ограниченные физические тесты и полный bootstrap выбранного GSI.


## Данные владельца и этап изоляции (0.1.5)

Владелец предоставил schema-2 JSON, собранный предыдущим APK на телефоне.
Исходный отчёт с PID/starttime в Git не добавлен. В профиле сохранены только
производные аппаратные/служебные факты и SHA-256 источника.

Подтверждено в этом наблюдении: UID 0, SELinux Enforcing, API 36 / arm64-v8a,
ядро 6.1.145-android14-11-maybe-dirty, температура 27,8 C и стабильные snapshots
14 работающих служб. Это не подтверждает тип root, пригодность гостя,
работу HAL после takeover или возможность восстановления после сбоя.

### Fingerprint и идентичности

Фактический fingerprint содержит точный build ID `BP2A.250605.031.A3_V000L1`,
а metadata OTA — `BP2A.250605.031.A3`. Компилятор и device совпадают.
Добавлен ровно один наблюдавшийся полный fingerprint; произвольные суффиксы,
другие сборки/API/ABI не разрешаются. `ota_identity_match` по-прежнему означает
точное совпадение исходного OTA fingerprint. Отдельный `host_profile_match`
учитывает два явно перечисленных значения. Launch gate остаётся закрыт.

Observed identity хранит UID, **отдельный первичный GID**, точное множество
supplementary groups, CapEff и SELinux context. Например, у Composer UID 1000,
GID 1003, supplementary group 1026. Подмена GID значением UID или добавление
primary GID в supplementary groups не считается совпадением.
Native probe сверяет эти данные; reviewer независимо проверяет drift.
Эти таблицы не применяют credentials и не запускают vendor binaries.

В отчёте активен vendor.gatekeeper_default с контекстом
vendor_hal_gatekeeper_qti. У SPU-варианта нет init property. Это зафиксировано
как наблюдавшийся выбор альтернативы, а не как доказательство отсутствия
бинарника. Неактивная SPU-служба не требуется, пока ожидаемая default-служба
работает стабильно; её исчезновение или активация SPU требуют разбора.
Контекст vendor_thermal-engine с дефисом обрабатывается без ложного отказа.

### Физические кнопки

Возвратные устройства выбираются по profile-named источникам и capabilities:
`gpio-keys` с Volume Up и `pmic_resin` с Volume Down. Event numbers не закреплены.
Гарнитура, также объявляющая обе клавиши, исключается. Дубликаты, ошибки ioctl
и неоднозначные источники не проходят проверку. Фактическое удержание комбинации
и возврат из гостевой сессии всё ещё не проверялись.

### Cgroup

Пустой cgroup.controllers не означает, что cgroup2 или cgroup.kill отсутствуют:
controllers описывают управление ресурсами, а не доказывают доступность kill.
См. [документацию ядра](https://docs.kernel.org/admin-guide/cgroup-v2.html).
По исходному отчёту версия FS и cgroup.kill оставались непроверенными.
Новый read-only JSON фиксирует statfs, self cgroup, boot ID и root context.

В APK есть отдельная кнопка **«Root-отчёт + тест cgroup»**. Она сначала собирает
read-only snapshot, затем только при точном профиле хоста запускает тест.
Тест требует UID 0 и Enforcing, проверяет тип cgroup2 у /sys/fs/cgroup,
создаёт новую уникальную группу mode 0700 и два собственных дочерних процесса.
Родитель и процессы OriginOS в неё не переносятся. cgroup.subtree_control,
ресурсные лимиты, mounts и SELinux не меняются.

Перед cgroup.kill проверяются pidfd обоих детей, точный список участников
и populated=1. После записи проверяются завершение обоих, populated=0,
reap и удаление группы. При ошибке group-kill не используется как cleanup:
убиваются только созданные тестом, ещё не reaped дочерние PID. В отдельном
процессе теста SIGCHLD временно переводится в default, чтобы IDs не могли
переиспользоваться до waitpid; старое disposition возвращается. Не переносите
этот core в многопоточный процесс с чужим reaper без отдельного дизайна.

У детей установлен parent-death SIGKILL; проверяется race с выходом родителя.
Внешний таймер probe — 12 секунд. При аварийном прерывании может остаться пустая
временная группа: это не выдаётся за успешную очистку. Путь созданной группы,
stage, errno, cleanup_errno и cleanup_complete включены в JSON.
Не пытайтесь вручную удалять чужие или населённые cgroup.

Для отдельного native-запуска:
```
adb shell su -c '/data/local/tmp/guardian-pd2425-preflight --test-cgroup'
```

0 означает успех child-only теста, 40 — отказ/ошибку теста, 31 — host mismatch.
Успешный тест всегда оставляет runtime_ready=false и не проверяет гостевой
namespace, FUSE/Binder, дисплей или восстановление хоста.

Комбинированный JSON имеет schema 3 и no_device_changes=false: временная группа
и дочерние процессы действительно создавались или могли создаваться. При этом
observations_read_only=true относится к исходному snapshot; тест записан в
self_tests.cgroup. Reviewer связывает его с snapshot по точному fingerprint и
boot ID и проверяет все результаты, включая cleanup. Одного passed=true мало.
Никаких данных автоматически не отправляется. Сохраните JSON прежней кнопкой.

### Watchdog и touch

watchdog0 не найден и watchdog fd у system_server не наблюдался. Это не
доказывает отсутствие аппаратного/OEM watchdog. Новая диагностика дополнительно
перечисляет /sys/class/watchdog, не открывая watchdog devices и не меняя timeout,
options или keepalive. Samsung adoption-контракт не отключён и не заменён
фиктивным успехом; стратегия восстановления Vivo остаётся незавершённой.

Для дальнейшего разбора VTS собираются только имена/права/владельцы узлов
/sys/class/vts/vivo_ts, /sys/touchscreen и Goodix module parameters. Значения
атрибутов жестов, IMEI, калибровки и биометрии не читаются. Протокол записи
состояния дисплея/тача по наличию этих узлов не объявляется подтверждённым.

### Проверки этого этапа

Тесты подтверждают точное разрешение SKU-fingerprint и отказ для другого SKU,
разделение primary/supplementary GID, drift capabilities/context, исключение
гарнитуры и неоднозначных кнопок, controllerless cgroup2 classification и
связывание self-test с boot ID. Cgroup core проверен с настоящими собственными
дочерними процессами/pidfd и подставной FS: отказ mkdir/add/kill/cleanup,
отказ при постороннем участнике, сохранность отдельного sentinel и inherited
SIGCHLD=SIG_IGN. Эти тесты не создают cgroup на машине CI.

На телефоне сам child-only тест ещё должен выполнить владелец. После него всё
равно остаются watchdog recovery, display/touch handoff, enforcing guest policy
и полный bootstrap GSI. Пропуск этих условий не включён.
